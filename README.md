# One Food Note

A single-file study library of poultry and food-safety material — class notes, interactive
trainers, Word notes and anatomy figures — published to GitHub Pages.

**Live:** https://drdoombg.github.io/One-Food-Note/

Everything is inside `index.html`. The page loads nothing from the network: documents are
gzip + base64 and revived at click time with `DecompressionStream`, images are inlined WebP.
~16 MB of sources compress to a ~4.5 MB page that works offline and from `file://`.

`PROJECT.md` is the working spec — how the build assembles the file, the UI contract, the
colour taxonomy, and the traps already hit. Read it before changing anything.

## What's in the repo

| Path | What it is |
|---|---|
| `index.html` | **The deliverable.** Generated by `_build/build.py` — never hand-edit. |
| `PROJECT.md` | Build + UI spec and the list of traps not to reintroduce. |
| `favicon.svg` | Icon source — notebook glyph on the `#1f5f8b` accent. |
| `favicon-32.png`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png` | Raster icon set. |
| `_build/head-icons.html` | The `<head>` block that embeds the icons as data URIs. |
| `.nojekyll` | Stops Pages from hiding `_build/`. |

The build sources (`_build/build.py`, `_build/shell.html`, the `.docx` / `.png` / `.pdf`
originals, `Anatomy and Physio/`) are not in this commit — add them when convenient so the
page can be rebuilt from scratch.

## Icons

The icons are embedded in `index.html` as data URIs, so the single-file contract holds —
the favicon and the iOS home-screen icon work offline and with no extra request. The
standalone files above are the reusable sources; the page does not reference them.

**After every rebuild, the icons must be put back.** `_build/build.py` regenerates
`index.html` from `_build/shell.html`, which does not yet carry them. Paste the contents of
`_build/head-icons.html` into `shell.html` immediately after its `<title>` line, once — then
every future build keeps them and this note can go.

To regenerate the icon files, re-run the generator that produced them against the header
glyph in `shell.html` (rounded square, `#1f5f8b`, white 1.5px notebook stroke on a 24×24
viewBox).

## Adding a note

Per `PROJECT.md`:

1. Drop the file in the folder (or `Anatomy and Physio/`).
2. `.docx` → the `NOTES` loop; image → the `IMG` loop; whole HTML page → the `DOCS` loop.
3. Add a card in `SECTIONS` in `_build/shell.html` under the right colour row, as
   `{n:"Name", type:"doc|rich|img", src:"key"}`, or inside a group's `kids`.
4. `python _build/build.py`, check the `unreferenced:` line is empty, commit.

Colour rows: `gold` = Poultry Bible only · `blue` = labs and micro · `green` = process,
packaging and NPD · `red` = anatomy, science and quality.

## Verifying a change

No test suite — headless Chrome is the harness:

```
google-chrome --headless=new --disable-gpu --virtual-time-budget=25000 \
  --dump-dom file:///path/to/index.html
```

The pattern that has caught every bug so far: copy `index.html`, inject a probe script before
`</body>` that exercises the UI and writes its findings into `document.title`, then grep the
title out of the dumped DOM. Worth asserting on each commit:

- `DOCS` / `NOTES` / `A` key counts are what you expect
- one `DOCS` entry gunzips to HTML of the right length
- every `A` entry's base64 starts `UklGR` (a real WebP)
- `document.querySelectorAll('.card').length` matches `SECTIONS`
- every `href="#x"` in an embedded document has a matching `id`

Current baseline: `DOCS=4 · NOTES=5 · A=47 · cards=7`, bible revives to 288,664 chars.

Requires `DecompressionStream`: Chrome/Edge 80+, Firefox 113+, Safari 16.4+.
